22:T380b,<p>Entire and Sarvam announced a partnership on November 25, 2026, to bring Sarvam models into Entire&#39;s agent-native Git workflow for developers in India. The companies say developers can host code in Entire&#39;s India region and use Sarvam models for agent runs, keeping code and AI inference within the country when the India region is selected.</p>
<p>The integration is tied to Trails, Entire&#39;s workflow for agent-assisted coding and review. Sarvam models are available in preview for projects that use India as their primary region. The announcement is relevant to Indian engineering teams that need local code hosting or want to evaluate AI-assisted development with an India-based model provider.</p>
<h2 id="news-summary">News Summary</h2><p>Entire, a developer platform founded by former GitHub CEO Thomas Dohmke, announced an integration with Sarvam, an Indian AI platform. The company says the partnership creates an agent-native Git forge with data residency in India. Developers can create, migrate, and host private repositories in the India region and run coding agents using Sarvam models on Trails.</p>
<p>Entire&#39;s <a href="https://entire.com/news/entire-partners-with-sarvam-to-complete-indias-sovereign-software-loop">official announcement</a> and its <a href="https://entire.com/blog/introducing-sarvam-ai-for-a-sovereign-software-loop-in-india">Sarvam integration blog</a> are dated November 25, 2026. ETEnterpriseAI reported the partnership at 10:29 AM IST on the same date, and IANS also covered the announcement later that day.</p>
<h2 id="what-happened">What Happened</h2><p>The partnership connects two parts of an AI-assisted software workflow. Entire provides the Git hosting and Trails workflow. Sarvam provides models that developers can select for agent runs. Entire says the integration is available in preview for developers who set India as the primary region for a project.</p>
<p>The company describes Trails as a replacement for the traditional pull request. The workflow brings developer intent, code, agent sessions, and review evidence together from the start of a task through to merge. Coding agents can address review findings in an iterative loop, while a human developer validates the changes before they are merged.</p>
<p>Entire&#39;s official blog explains the setup. A developer creates a project with India as its primary region, creates a repository inside that project, opens project settings, selects Agents, and creates a custom agent. The developer can then choose a Sarvam model in the model dropdown. The company also describes a Sarvam external agent plugin for tracking sessions through the CLI.</p>
<p>The <a href="https://entire.com/blog/everything-you-need-to-get-started-with-entire-in-india">official Entire setup guide</a> provides more detail about India-region projects and repositories. The <a href="https://enterpriseai.economictimes.indiatimes.com/news/industry/entire-partners-with-sarvam-to-bring-sovereign-ai-coding-to-india/136148694">ETEnterpriseAI report</a> and <a href="https://ianslive.in/india-gets-agent-native-git-forge-with-local-data-residency-via-entire-sarvam-tie-up--20261125132125">IANS coverage</a> also describe the partnership and the intended data-residency model.</p>
<h2 id="why-it-matters">Why It Matters</h2><p>AI coding tools can send code, prompts, context, and agent activity to systems outside the developer&#39;s own environment. For some organizations, that raises questions about data location, contractual controls, customer confidentiality, and sector rules. The location of the code repository is only one part of that question. Model inference, agent logs, backups, telemetry, and connected services also matter.</p>
<p>The Entire and Sarvam integration is aimed at teams that want more of the software workflow to stay in India. If a repository is hosted in the India region and the agent uses Sarvam models through the integration, the companies say code and inference can remain in the country. That may help teams that have data-residency requirements or prefer a local model provider for sensitive development work.</p>
<p>The second point is the workflow design. Traditional pull requests focus on the proposed code change and review conversation. Trails is designed to keep intent, agent sessions, and review evidence next to the code. That could help reviewers understand why an agent made a change, what instructions it received, and how the work progressed.</p>
<p>This does not remove the need for code review. An agent can generate a useful patch and still introduce a bug, weaken a security control, or misunderstand a requirement. A human developer must validate the change, run tests, and decide whether it should be merged.</p>
<h2 id="key-details">Key Details</h2><h3 id="code-hosting-and-model-inference-are-separate-parts">Code hosting and model inference are separate parts</h3><p>Entire provides the Git hosting and project region. Sarvam provides the models used for agent inference. The company says developers can set India as the primary region for a project and then select Sarvam as the model provider for a custom agent.</p>
<p>This distinction matters because code storage and model inference are separate technical services. An organization should confirm which data is sent to the model, where it is processed, how logs are stored, and what happens when a workflow calls an external connector. A local repository does not automatically prove that every part of a development workflow is local.</p>
<h3 id="sarvam-models-are-in-preview-on-trails">Sarvam models are in preview on Trails</h3><p>Entire says Sarvam models are available in preview to developers who set India as the primary region for a project. The integration is not described as a fully mature, generally available service for every account. Teams should check current access, model availability, and product terms before moving an important repository.</p>
<p>The official Entire blog also says developers can use Sarvam models for agent runs and track sessions through a Sarvam external agent plugin. The blog mentions support for Indian languages such as Hindi, Bengali, Marathi, and Kannada. The exact model and language capabilities should be checked in the current product interface.</p>
<h3 id="trails-keeps-agent-activity-near-the-code">Trails keeps agent activity near the code</h3><p>The Trails workflow is designed to preserve developer intent, code, agent sessions, and review evidence. The idea is to make agent-assisted changes easier to inspect than a patch that arrives without a clear record of how it was produced.</p>
<p>The product description says agents can address review findings in a loop while human developers validate changes before merge. That is an important distinction from a workflow that merges generated code automatically. Teams should still require tests, approvals, and a clear owner for each change.</p>
<h3 id="entire-shared-a-performance-benchmark">Entire shared a performance benchmark</h3><p>Entire&#39;s announcement says its open-source ForgeMark test measured 355 pushes per second for Entire, compared with 29 for Cursor Origin, 10 for GitLab, and four for GitHub in a test involving simultaneous agent-driven pushes and clones. These figures are company-reported results from its own benchmark. They should not be treated as an independent performance comparison for every repository or workload.</p>
<p>A Git hosting benchmark can be affected by repository size, network location, concurrency, hardware, caching, and test design. Teams should run their own tests with representative repositories and agent activity before choosing a hosting platform.</p>
<h2 id="who-is-affected">Who Is Affected</h2><p>The announcement is most relevant to Indian software teams that need code hosting in India and want to test AI-assisted development with a local model provider. Regulated organizations may be interested in the data-residency option, but they still need to review the full processing path and contractual terms.</p>
<p>Developers may be interested in Trails if they want review evidence and agent sessions to stay close to each code change. Engineering leaders may want to compare the workflow with their current Git hosting and pull request process. Security teams will need to review repository permissions, agent credentials, model access, audit logs, and data retention.</p>
<p>The partnership is less relevant to teams that only need a simple Git remote or that already have an approved coding-agent workflow with suitable data controls. Moving a repository is a business and engineering decision, not a requirement for using Sarvam models.</p>
<h2 id="what-happens-next">What Happens Next</h2><p>The immediate next step for interested developers is to test the preview. Entire&#39;s official guide describes creating an India-region project, creating a repository, opening the Agents settings, and selecting a Sarvam model for a custom agent. Teams should start with a non-sensitive repository and a limited set of tasks.</p>
<p>Before migrating a production codebase, verify how mirrors, backups, repository history, agent sessions, logs, and connected services are handled. Confirm whether the project region applies to all relevant data or only the repository and inference path described by the companies. Ask for contractual terms and security documentation that match your organization&#39;s requirements.</p>
<p>The announcement does not provide a full public price comparison, a detailed service-level agreement, or a complete list of enterprise compliance controls. It also does not establish that every regulatory obligation is satisfied simply by selecting an India region. Those questions need direct answers from the vendors.</p>
<h2 id="what-we-know-and-do-not-know">What We Know and Do Not Know</h2><p>What is confirmed is that Entire and Sarvam announced the integration on November 25, 2026. Entire says Sarvam models are available in preview for developers who set India as the primary region for a project. The company says the workflow keeps code hosting in India and uses Sarvam models for agent inference on Trails.</p>
<p>What remains unclear from the public announcement is the full technical and contractual scope of data residency. Organizations should ask about backups, telemetry, logs, model retention, support access, subprocessors, encryption, and disaster recovery. The announcement also does not provide an independent performance test or a complete pricing and availability matrix.</p>
<p>The best way to evaluate the partnership is to run a controlled pilot. Use a test repository, a small agent task, and a clear review process. Check the code location, the model provider, the audit trail, and the final diff. If the workflow meets the team&#39;s security and engineering requirements, then consider a wider rollout.</p>

<li>Trails combines code, agent sessions, and review evidence in an agent-focused development workflow.</li>
<li>Data residency is useful, but it does not replace a full security, legal, and operational review.</li>
