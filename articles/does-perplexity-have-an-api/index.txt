24:T346f,<p>Yes, Perplexity has a developer API. It is not limited to the consumer search website or mobile app. The current developer platform lists five core APIs for different jobs, including web-grounded answers, raw search results, model access, embeddings, and structured decisions.</p>
<p>The important change for developers is that Perplexity now recommends its Agent API for new work that previously used Sonar Chat Completions. The old Sonar quickstart redirects to a migration guide. If you are starting an integration today, use the current documentation instead of copying an older endpoint from a blog post.</p>
<h2 id="short-answer">Short Answer</h2><p>Perplexity offers an API platform with five core products: Agent API, Search API, Orchestrator API, Embeddings API, and Decisions API. The Agent API is the most direct starting point if your application needs a generated answer with web search and citations. The Search API is better when you want ranked results as JSON and plan to handle filtering or answer generation yourself.</p>
<p>The API uses a project and API key. Perplexity&#39;s current quickstart says API pricing is pay as you go and that no subscription is required. That is a separate developer workflow from signing in to the consumer Perplexity app. Before you build, check the current pricing page and usage tier for the API you plan to call.</p>
<h2 id="what-the-question-really-means">What the Question Really Means</h2><p>The phrase Perplexity API can refer to several different needs. A developer may want to send a question and receive an answer with sources. A search product may need raw web results to pass to its own ranking system. A retrieval system may need embeddings. Another application may need a structured yes-or-no answer or a model endpoint.</p>
<p>Those are not the same request. The Agent API is designed for a response that can use tools and web search. The Search API returns search results rather than a finished answer. The Embeddings API supports semantic search and retrieval-augmented generation. The Orchestrator API gives access to hosted models through compatible interfaces. The Decisions API returns typed outputs for questions that can be expressed with a defined answer format.</p>
<p>A consumer plan and a developer API key are also different. The API quickstart says that all APIs use pay-as-you-go pricing and no subscription is required. Treat API usage as its own developer billing path. Do not assume that signing in to a consumer account automatically gives your application an API key or an API credit balance.</p>
<h2 id="how-it-works">How It Works</h2><p>The Agent API is the main option for a conversational application. Perplexity describes it as a multi-provider interface with real-time web search, tool configuration, reasoning controls, and token budgets. Its documentation lists the endpoint as POST <a href="https://api.perplexity.ai/v1/agent">https://api.perplexity.ai/v1/agent</a>. The OpenAI-compatible POST /v1/responses path is also accepted as an alias.</p>
<p>The Agent API can return web-grounded answers with citations in one call. The developer can select a supported model, pass an input prompt, and choose tools such as web search. This is useful when the application needs a final response rather than a list of links. It also means that the application should inspect the returned status and output instead of assuming every request completed successfully.</p>
<p>The Search API is a different product. It returns ranked web results as structured JSON. The documentation says it does not generate an answer and does not use token billing in the same way as the Agent API. It is useful when your own application needs to filter, store, or pass results to another model. You can use it as the search layer in a larger pipeline.</p>
<p>The other APIs serve narrower jobs. Orchestrator provides access to open-weight models hosted by Perplexity through compatible endpoints. Embeddings creates vectors for semantic search and retrieval systems. Decisions returns typed answers with probabilities for supported question formats. The best API is the one that matches the output your application actually needs, not the one with the broadest name.</p>
<p>Perplexity&#39;s current docs also matter for older integrations. The former Sonar Chat Completions quickstart now points to a migration guide for the Agent API. The documentation presents Agent API as the next interface for production work. If you maintain an older Sonar integration, read the <a href="https://docs.perplexity.ai/docs/agent-api/migrate-from-sonar/overview">migration guide</a> before changing code.</p>
<h2 id="practical-steps">Practical Steps</h2><p>Start by choosing the output. If your app needs an answer with citations, begin with Agent API. If it needs raw ranked pages, use Search API. If it needs vector representations, review Embeddings. This choice will affect the response format, pricing, and the amount of work your own application must do.</p>
<p>Next, create a project in the Perplexity API console. The API key guide says you must create a project before generating keys. You can use separate keys for development and production so that a test script does not share the same credential as a deployed application.</p>
<p>When the key appears, save it immediately. Perplexity says the full token is shown only once and cannot be retrieved later. Put it in an environment variable such as PERPLEXITY_API_KEY. Never paste it into browser JavaScript, a mobile app, a public repository, or a URL. If a key is exposed, revoke it and update the application with a new one.</p>
<p>A basic Agent API request uses a bearer token and a JSON body. The current quickstart shows this endpoint and a model field. The model name below is an example from the documentation, not a promise that it is the best choice for every application.</p>
<pre><code class="language-bash">curl https://api.perplexity.ai/v1/agent   -H &quot;Authorization: Bearer $PERPLEXITY_API_KEY&quot;   -H &quot;Content-Type: application/json&quot;   -d &#39;{
    &quot;model&quot;: &quot;openai/gpt-5.6-sol&quot;,
    &quot;input&quot;: &quot;Summarize the latest public documentation for this product.&quot;
  }&#39;
</code></pre>
<p>After the first successful call, add basic production controls. Set request timeouts, log request IDs and usage, handle incomplete responses, and return a clear error when the provider rejects a request. Keep model names and tool settings in configuration so you can change them without rewriting the whole application.</p>
<p>Finally, review pricing and rate limits before sending real traffic. Perplexity says usage tiers determine request and token limits and are based on cumulative API spending. Higher tiers can unlock higher limits. Your own application should still use retries with backoff, queue expensive tasks, and stop retrying when an authentication or billing error requires human action.</p>
<h2 id="common-problems">Common Problems</h2><p>A common integration error is using an older Sonar endpoint because a tutorial still shows it. The current documentation redirects the old Sonar quickstart to the Agent API migration guide. Read that guide before copying a request from an older article. The current Agent API path is /v1/agent, and /v1/responses is listed as an alias.</p>
<p>An authentication error can mean that the key was copied incorrectly, revoked, or created in a different project. Perplexity says the full key is shown only once. Check that the environment variable is loaded in the server process and that the request uses the Bearer authorization header. Do not print the full key in logs while debugging.</p>
<p>A rate-limit error can occur when the application sends more requests than its current usage tier allows. Perplexity documents usage tiers based on cumulative spending. Check the API console for the current tier and the rate-limit documentation. A fixed retry loop can make the problem worse, so use backoff and a maximum retry count.</p>
<p>Another mistake is expecting Search API to return a written answer. Search API gives ranked results as JSON. If your user interface needs a summary, you must generate one in your own application or call Agent API. Choose the response type before building the rest of the pipeline.</p>
<h2 id="what-does-not-work">What Does Not Work</h2><p>A Perplexity Pro login is not the same as a developer API key. A consumer account lets a person use the product interface. An API integration needs a project, key, billing setup, and a server-side request. The official API quickstart says the APIs use pay-as-you-go pricing and no subscription is required, so check the developer console rather than assuming your app can use a consumer-plan allowance.</p>
<p>A Search API request is also not a drop-in replacement for an answer endpoint. It returns raw search results. If you need citations in a generated explanation, use Agent API or build the answer stage yourself. Do not expect the Search API to make editorial choices about which sources matter or to write a final paragraph.</p>
<p>Do not put the API key in a public frontend. Browser code can be inspected, and a key exposed there can be copied and used by someone else. Route requests through your own backend, apply usage limits, and store the key in a secure environment variable or secret manager.</p>
<h2 id="safety-and-limitations">Safety and Limitations</h2><p>A web-grounded response can still contain errors. Citations make it easier to check claims, but they do not guarantee that every source is authoritative or that the summary is complete. For financial, medical, legal, or security decisions, validate the source material directly and make the limits of your application clear to users.</p>
<p>Treat API keys as credentials. Perplexity&#39;s key-management guide says a new key is shown only once and should be stored securely. It recommends environment variables and key rotation. Avoid sharing keys across unrelated projects, and revoke keys that are no longer needed.</p>
<p>The platform and model list can change. Check the API changelog, pricing, and rate-limit pages before shipping an integration. The guidance in this article reflects the official documentation reviewed on November 10, 2026. Use the current <a href="https://docs.perplexity.ai/docs/getting-started/quickstart">Quickstart</a>, <a href="https://docs.perplexity.ai/docs/agent-api/quickstart">Agent API guide</a>, and <a href="https://docs.perplexity.ai/docs/search/overview">Search API overview</a> as the source of truth.</p>
<h2 id="key-takeaways">Key Takeaways</h2><ul>
<li>Yes, Perplexity has a developer API with five core products.</li>
<li>Agent API returns generated, web-grounded responses; Search API returns ranked results.</li>
<li>API billing is pay as you go, with usage tiers and rate limits.</li>
<li>The current Agent API endpoint is /v1/agent, not an old Sonar tutorial endpoint.</li>
<li>Create a project, save the key once, and keep it server-side.</li>
</ul>
