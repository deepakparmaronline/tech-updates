22:T2c87,<p>This is a practical guide, not a new November 7 launch report. OpenAI announced the Agents API in public beta on September 10, 2026. The current developer documentation describes a managed agent harness built around an agent, an execution environment, a durable session and a stream of events. This guide shows how to think about a first workflow and where to add checks before real data or write access is involved.</p>
<h2 id="news-summary">News Summary</h2><p>The Agents API is an existing developer interface for building and running cloud agents. It gives an application a way to create an agent, choose the tools and instructions it can use, select an environment and continue work through a durable session. The API is not a new announcement in the November 6 to 7 research window. The original public-beta announcement was published on September 10, 2026.</p>
<p>The useful change for developers is the managed harness. Instead of writing every orchestration step from scratch, an application can create a session, send input, stream events and continue the same session. The application still owns its product logic, user experience, permissions and approval rules.</p>
<h2 id="what-happened">What Happened</h2><p>OpenAI&#39;s September announcement introduced the Agents API as a way to build and run cloud agents with the Codex harness managed by OpenAI. The current API documentation describes four core concepts: an Agent, an Environment, a Session, and Events and Items. Together they describe what the agent can do, where it works, how its task continues and what the application receives.</p>
<p>This article is a guide to the current documentation, not a claim that OpenAI launched the API today. Developers should use the live API reference and changelog before copying code into a production service. A public beta can change its methods, permissions and limits.</p>
<h2 id="who-is-affected">Who Is Affected</h2><p>The API is aimed at developers building multi-step agents that need to use tools, work with files or continue a task across more than one turn. It can be useful for a coding assistant, an internal research tool, a support workflow or an application that delegates a task and reports progress.</p>
<p>It is not necessary for every chatbot. If an application only needs to answer a short question, a simpler model request may be easier to maintain. The Agents API becomes more relevant when the work needs an environment, tool calls, session state or orchestration across several steps.</p>
<h2 id="key-details">Key Details</h2><h3 id="start-with-the-agent-definition">Start with the agent definition</h3><p>An agent is the model, instructions, tools and MCP servers available to the task. Keep this definition narrow. Give it one clear role, list only the tools it needs and state what it must not do. A research agent does not need permission to delete files. A report writer does not need a payment tool.</p>
<p>Use instructions that describe the expected output and the conditions for stopping. Ask the agent to cite sources, identify uncertainty and report failed tool calls. Avoid instructions such as &quot;do everything necessary&quot; because they make it hard to predict what the agent will try next.</p>
<h3 id="choose-the-environment-deliberately">Choose the environment deliberately</h3><p>The environment is an optional sandbox or computer where the agent can access files and run commands. OpenAI&#39;s quickstart shows an OpenAI-hosted environment for a simple coding task. The documentation also describes an environment type of none for agents that answer questions or call external tools without running commands or working with local files.</p>
<p>Do not add a sandbox just because the API supports one. If the task is a source-backed question, no local file environment may be needed. If the task needs code or files, define the workspace and the permissions before the agent starts. Keep network access and filesystem access as narrow as the task allows.</p>
<h3 id="create-a-durable-session">Create a durable session</h3><p>A session is an instance of an agent that can receive input and continue work. Your application creates the session, sends a task and receives events. It can stream progress or use webhooks to learn when the agent finishes or needs more input. It can then continue or steer the same session.</p>
<p>This model is useful for work that takes longer than one response. A session can keep state and resume where it left off. It also means your application must manage session identifiers, access control and deletion. Do not expose a session ID as if it were a public share link.</p>
<h3 id="follow-events-not-only-the-final-text">Follow events, not only the final text</h3><p>The API streams events and items while the agent works. OpenAI&#39;s quickstart says to look for the completed-turn event and then check the reported execution result. A completed turn does not guarantee every tool succeeded. The documentation also describes failed, cancelled and session-failed events.</p>
<p>Build your application so it records the event stream and checks the final result before telling a user that a task succeeded. If the stream disconnects, retrieve the saved session and items before retrying. Starting a second session too early can duplicate work or produce two conflicting outputs.</p>
<h2 id="why-it-matters">Why It Matters</h2><p>A managed harness can reduce the amount of custom infrastructure a team needs for long-running agents. The API documentation describes support for sandboxed commands, skills and instructions, external tools and MCP, steering, context summarisation, subagents and session resumption. Those capabilities can make a workflow easier to extend, but they do not remove the need for engineering controls.</p>
<p>The most important design choice is still the boundary around the agent. Decide what it can read, what it can change and which actions need a human approval. For example, an agent can draft a pull request without being allowed to merge it. It can prepare an email without sending it. It can calculate a payment without being able to move money.</p>
<h2 id="what-we-know-and-do-not-know">What We Know and Do Not Know</h2><p>OpenAI&#39;s current documentation says the Agents API retains session state so work can continue across turns. It says sessions and published artifacts can be deleted when no longer needed. It also states that the API currently supports data residency only in the United States and does not support Zero Data Retention. Choosing a self-hosted sandbox does not make the Agents API ZDR-eligible.</p>
<p>These are important constraints for teams handling regulated or sensitive information. A self-hosted environment does not remove the API&#39;s own data-retention rules. Review OpenAI&#39;s current data controls and your organisation&#39;s requirements before sending customer data, source code or internal documents.</p>
<p>The original September announcement described a public beta. The current documentation is the source of truth for the methods and capabilities available now. Do not assume a beta feature has the same stability, support or pricing as a generally available service.</p>
<h2 id="what-happens-next">What Happens Next</h2><p>A safe first project should begin with a low-risk task. Use a read-only research or code explanation workflow. Record the input, streamed events and final output. Test how the agent behaves when a tool fails, a source is missing or a task is interrupted. Then add write actions one at a time.</p>
<p>Before production, measure the full workflow rather than only the model response. Track tool success, latency, cost, failed sessions, retries and the number of tasks that need human correction. Keep a clear route for a person to cancel the task or review a proposed action. Recheck the API changelog before each release.</p>
<h2 id="final-takeaway">Final takeaway</h2><p>The Agents API is useful when a product needs more than a single model response. Its agent, environment, session and event model gives developers a structured way to run long tasks. The safest implementation is not the one with the most tools. It is the one with a small permission set, clear stop conditions and a human review step for important actions.</p>
