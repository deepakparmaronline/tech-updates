1b:T2af8,<p>OpenAI announced GPT-6.1 Terra on October 26, 2026, describing it as a faster, lower-cost model for visual reasoning, computer use and professional tasks. It is available through the OpenAI API and in ChatGPT Work and Codex for eligible Plus, Pro, Enterprise and Edu users. OpenAI lists standard API pricing at $1 per million input tokens, $0.05 per million cached input tokens and $5 per million output tokens.</p>
<p>The release matters most to developers building AI agents and businesses that automate computer-based work. However, the performance figures in the launch post are OpenAI&#39;s own benchmark claims, not a guarantee that the model will perform best on every workflow.</p>
<h2 id="news-summary">News Summary</h2><p>GPT-6.1 Terra is positioned for tasks that combine reading visual information with taking actions through software. OpenAI highlights work such as interpreting technical drawings, filling forms, editing videos and processing incoming invoices. Its main commercial pitch is that the model can handle many everyday tasks at lower cost than higher priced models in the same family.</p>
<p>The model is available in the API as gpt-6.1-terra. OpenAI says it can also be used in ChatGPT Work and Codex by Plus, Pro, Enterprise and Edu users. Developers should confirm current availability, model parameters and API requirements in the official <a href="https://developers.openai.com/api/docs/models/gpt-6.1-terra">GPT-6.1 Terra model documentation</a>.</p>
<h2 id="what-happened">What Happened</h2><p>OpenAI&#39;s <a href="https://openai.com/index/introducing-gpt-6-1-terra/">October 26 announcement</a> describes Terra as a model that combines detailed visual reasoning, computer use and natural writing. The company says standard API prices are 50% lower than those of GPT-5.6 Terra and GPT-6.1 Sol. The <a href="https://developers.openai.com/api/docs/changelog">OpenAI API changelog</a> also records GPT-6.1 Terra as released on October 26.</p>
<p>The announcement presents Terra as a cost-efficient option for high-volume professional work rather than the best choice for every possible task. OpenAI says its more capable models remain preferable for some of the most complex coding work. This makes the release a model selection decision: a team may use Terra for routine workflows and reserve more expensive models for cases that require them.</p>
<p>OpenAI lists the standard API rates as $1 per million input tokens, $0.05 per million cached input tokens and $5 per million output tokens. Actual bills depend on the amount of input and output, cache use, tools and the structure of the workflow. The advertised per-token price alone does not determine the cost of a completed task.</p>
<h2 id="why-it-matters">Why It Matters</h2><p>Computer use is an important step beyond generating a block of text. An agent may need to interpret a screen, decide which control to use, enter data, check a result and recover from an error. A model that can handle these steps reliably may help automate repetitive office work, data entry, software testing and document processing.</p>
<p>Lower token prices can also make it practical to run more attempts or process larger batches. But cheaper tokens do not automatically mean cheaper outcomes. A model that needs repeated retries, creates errors or requires heavy human correction can cost more overall than a model with a higher per-token price.</p>
<p>For organizations, the useful question is whether Terra reduces the total cost per correctly completed task. That includes model usage, tool calls, latency, failed actions, monitoring and human review. A meaningful evaluation should compare complete workflows rather than only the price of a million tokens.</p>
<h2 id="key-details">Key Details</h2><h3 id="availability">Availability</h3><p>OpenAI says GPT-6.1 Terra is available in ChatGPT Work and Codex for Plus, Pro, Enterprise and Edu users. Developers can call it through the API using the model identifier gpt-6.1-terra. Availability may depend on the product surface, account and API configuration, so check the official documentation before planning a deployment.</p>
<h3 id="pricing">Pricing</h3><p>The standard prices listed by OpenAI are $1 per million input tokens, $0.05 per million cached input tokens and $5 per million output tokens. Cached input can lower costs when repeated context qualifies for caching. Teams should not assume every request will receive the cached rate; confirm cache behavior and calculate cost using their real prompt patterns.</p>
<h3 id="visual-reasoning-and-computer-use">Visual reasoning and computer use</h3><p>OpenAI highlights tasks involving images, technical drawings and desktop software. The company reports results on benchmarks such as Agents&#39; Last Exam, MMMU-Pro and OSWorld 2.1. These are different tests of professional task execution, visual reasoning and computer use. A benchmark score does not prove that an agent will operate safely in a particular business system.</p>
<h3 id="coding-and-factuality-claims">Coding and factuality claims</h3><p>The announcement reports improved results on OpenAI&#39;s internal error-inducing prompts and Terminal-Bench 4.0. Because the company is reporting its own results, readers should treat these as vendor claims and inspect the benchmark setup. Independent reproduction and task-specific testing are useful before changing a production system.</p>
<h2 id="who-is-affected">Who Is Affected</h2><p><strong>Developers building agents</strong> should evaluate Terra if their systems use screenshots, browser interactions, desktop software or repeated professional tasks. The model may be attractive where token cost matters, but computer-use tools need clear permission boundaries.</p>
<p><strong>Businesses automating office workflows</strong> can test use cases such as reading invoices, classifying documents or entering information into internal systems. Start with a sandbox or sample dataset, and keep a person responsible for confirming consequential changes.</p>
<p><strong>Teams already using OpenAI models</strong> may want to compare Terra against the model they currently use. They should test whether it meets their quality threshold before changing the default model across every task.</p>
<p><strong>Organizations with strict data controls</strong> should review logging, access permissions, retention and the systems the agent can reach. A model release does not replace a security review of the agent&#39;s tools or environment.</p>
<h2 id="what-happens-next">What Happens Next</h2><p>The next useful evidence will come from real deployments and independent evaluations. Developers should compare task success, tool selection, error recovery, latency and total cost. They should also test whether the model follows scope restrictions and asks for help when it encounters a blocker.</p>
<p>If you plan to switch, run both models on a representative set of anonymized tasks. Record successful completions, incorrect outputs, retries, intervention time and API usage. Use a rollback path and avoid giving a new model access to production systems until its behavior is understood.</p>
<p>OpenAI may update model documentation, pricing and availability. Check the official <a href="https://developers.openai.com/api/docs/models/gpt-6.1-terra">model page</a> and <a href="https://developers.openai.com/api/docs/changelog">API changelog</a> for the latest details instead of assuming the launch post will remain the final specification.</p>
<h2 id="what-we-know-and-do-not-know">What We Know and Do Not Know</h2><p>We know OpenAI announced GPT-6.1 Terra on October 26, 2026, and that the company lists it for API use and eligible ChatGPT Work and Codex accounts. The official announcement also gives standard API pricing and describes its focus on visual reasoning and computer use.</p>
<p>We do not know from the launch post alone how it will perform on every independent workload, how often it will make mistakes in a specific company&#39;s environment or how much total cost it will save after retries and human review. OpenAI&#39;s benchmark claims should be attributed to OpenAI, and results should not be generalized beyond the test conditions.</p>
<p>The announcement also does not mean that every task should be handed to an autonomous agent. Computer use can affect real applications, so organizations still need scoped credentials, confirmations for sensitive actions, logging and a clear way to stop or reverse a task.</p>
