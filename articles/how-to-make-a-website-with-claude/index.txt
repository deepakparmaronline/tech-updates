19:T3549,<p>You can make a website with Claude in two main ways. Use Artifacts when you want a quick prototype, small interactive tool or single-page website. Use Claude Code when you need to work with a real project, edit files, run commands and prepare a site for deployment.</p>
<p>The choice matters. A quick demo and a production website have different needs. This guide explains both paths, how to write a useful brief, how to test the result and what you still need to do before publishing.</p>
<h2 id="short-answer">Short Answer</h2><p>Claude can help you plan, design and build a website. For a quick result, start with <a href="https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them">Claude Artifacts</a>. Anthropic says Artifacts can create interactive outputs such as web experiences, small tools and single-page websites. You can refine the result in the conversation and share or export it.</p>
<p>For a multi-page site or a project that must live in your own code repository, use <a href="https://docs.anthropic.com/en/docs/claude-code/overview">Claude Code</a>. It can inspect a project, edit files and run development commands. This is a better fit when you need reusable components, a database, forms, tests, a build process or a deployment pipeline.</p>
<p>Claude does not remove the need for a clear plan. You still need to decide what the site should do, provide accurate content, review the code and test it on real devices. Claude can speed up the work, but it cannot guarantee that the result is secure, accessible or ready for customers.</p>
<h2 id="what-the-question-really-means">What the Question Really Means</h2><p>People often ask how to make a website with Claude as if there were one button that creates a complete business website. In practice, the best workflow depends on the size and purpose of the site.</p>
<p>A landing page for an idea may need only a headline, a few sections and a contact button. An online store needs product data, payments, order handling and customer support. A company website may need several pages, a content management system, analytics, privacy controls and a reliable deployment process. These projects should not use the same setup.</p>
<p>You should also decide whether you need a prototype or a site that you will maintain. A prototype helps you test a layout or explain an idea. A production site needs source control, backups, testing, security updates and a plan for future content changes.</p>
<p>Claude offers different ways to help with these jobs. Artifacts is the easiest route for a small web experience. Claude Code is more flexible for a real codebase. Claude Design can help with visual concepts and prototypes, but the final site still needs to be implemented and reviewed.</p>
<h2 id="how-it-works">How It Works</h2><p>Artifacts are created inside a Claude conversation. You describe the result you want, Claude builds an interactive artifact, and you can ask for changes. The <a href="https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them">official Artifacts guide</a> describes supported outputs such as small applications, visualisations and single-page websites. This is useful when you want to see an idea quickly without setting up a local development environment.</p>
<p>Claude Code works with files and commands in a project. Anthropic&#39;s <a href="https://docs.anthropic.com/en/docs/claude-code/overview">Claude Code overview</a> explains how it can understand a codebase, make changes and help with development tasks. The <a href="https://code.claude.com/docs/en/quickstart">quickstart guide</a> shows how to start a session and work with a project. This approach gives you more control over the folder structure, framework, packages and tests.</p>
<p>The two options are not competitors in every situation. You can use Artifacts to test the layout and user flow, then use Claude Code to build a maintainable version. You can also ask Claude to prepare a sitemap, page content and component plan before any code is written.</p>

<h2 id="practical-steps">Practical Steps</h2><h3 id="1-write-a-short-website-brief">1. Write a short website brief</h3><p>Tell Claude who the website is for, what it should help visitors do and what information must appear. Include the business name, audience, main service, location, contact details and any required pages. If a fact is missing, tell Claude to use a placeholder instead of inventing one.</p>
<h3 id="2-ask-for-the-sitemap-before-the-design">2. Ask for the sitemap before the design</h3><p>Request a page list and a simple explanation of what each page needs. A small company site may need Home, About, Services, Projects, Blog and Contact. An online tool may need a landing page, documentation, pricing and support. Review the structure before asking for code.</p>
<h3 id="3-choose-artifacts-or-claude-code">3. Choose Artifacts or Claude Code</h3><p>Use Artifacts if the goal is to show a single-page idea or test an interaction. Use Claude Code if you need a project with multiple routes, reusable components, local files, a build command or a database. Do not start with a complex framework when a small prototype is enough.</p>
<h3 id="4-set-the-design-rules">4. Set the design rules</h3><p>Describe the layout, colours, font style, spacing, navigation and mobile behaviour. Ask for readable contrast, clear buttons, visible focus states and consistent headings. Provide a reference image or an existing brand guide if you have permission to use it.</p>
<h3 id="5-build-one-section-at-a-time">5. Build one section at a time</h3><p>Ask Claude to create the header and hero section first. Review the result, then add the next section. This makes it easier to catch layout problems before they spread across the site. For a multi-page project, ask Claude to create reusable components rather than copying the same markup into every page.</p>
<h3 id="6-add-real-content-and-working-actions">6. Add real content and working actions</h3><p>Replace placeholder text with verified information. Test every button, navigation link, form and download. A contact form is not complete just because it looks correct. It needs a working destination, validation and a clear success or error message.</p>
<h3 id="7-check-mobile-accessibility-and-seo">7. Check mobile, accessibility and SEO</h3><p>Test the page at phone, tablet and desktop widths. Check heading order, image alt text, keyboard navigation, colour contrast and form labels. Add unique page titles and meta descriptions, canonical URLs where needed, Open Graph data, a sitemap and a robots file.</p>
<h3 id="8-run-tests-and-prepare-deployment">8. Run tests and prepare deployment</h3><p>With Claude Code, ask it to run the project&#39;s lint, tests and production build. Review the changed files and fix errors before deployment. Then connect the repository to the hosting provider you choose. Claude can help prepare the steps, but you must control the domain, hosting account and production credentials.</p>
<p>A useful starting prompt is:</p>
<blockquote>
<p>Build a responsive website for [business or project]. First return a sitemap, page goals, component list and questions about missing content. Do not invent facts, prices, contact details or customer reviews. Use accessible semantic HTML, mobile-first layout, unique page titles and descriptions, and clear form validation. After the build, run the available checks and list every file changed.</p>
</blockquote>
<p>This prompt is more useful than saying only &quot;make a modern website&quot;. It gives Claude a task, constraints and a way to check the result.</p>
<h2 id="common-problems">Common Problems</h2><p>A vague brief often creates a generic site. If you do not provide the audience, goal or content, Claude must guess. The result may look polished but say very little. Give it real information and ask it to identify gaps before building.</p>
<p>Another problem is a page that looks complete but has non-working features. A button may not submit a form. A menu may not open on mobile. A search box may be decorative. Ask Claude to list the expected behaviour for every interactive element and test each one.</p>
<p>Generated code can also introduce dependencies or change files that were not part of the task. With Claude Code, ask for a plan before large changes. Review the diff, run tests and keep a clean version-control history. If the build fails, provide the actual error message instead of asking for a general fix.</p>
<p>SEO problems often appear at the end. A page may have repeated titles, missing descriptions, large images, weak internal links or no canonical URL. Include the SEO requirements in the first brief and check them before launch.</p>
<h2 id="what-does-not-work">What Does Not Work</h2><p>One vague prompt is not a reliable way to create a complete production website. It may generate a good first screen, but it will not know your business rules, legal requirements, data model or hosting setup unless you provide them.</p>
<p>Do not assume an Artifact is the same as a full production website on your own domain. Artifacts are useful for sharing and testing a web experience inside Claude. A production site may need a custom domain, server-side code, database, monitoring, backups and a deployment pipeline.</p>
<p>Do not ask Claude to publish a site using real credentials pasted into a chat. Do not accept invented testimonials, prices, policies or company details. Do not skip tests because the page looks correct in one browser preview.</p>
<h2 id="safety-and-limitations">Safety and Limitations</h2><p>Review all code before it reaches production. Check dependencies, form handling, access control, API calls and data storage. Keep secrets in environment variables or your hosting provider&#39;s secret manager, not in source files or prompts. Use test data while developing.</p>
<p>If the website collects names, email addresses, payments or other personal information, decide how the data will be stored and who can access it. Add a privacy notice that matches the real process. Do not copy a generic policy and assume it covers your site.</p>
<p>Check image and font licences before publishing. If Claude creates an image or layout based on a reference, make sure you have the right to use the source material. Also check accessibility with a keyboard and screen reader where possible.</p>
<p>Claude may produce code that works in a preview but fails in a real browser or after deployment. Test the production build, mobile layout, redirects, forms and analytics. Keep a backup and a way to roll back a failed release.</p>
<h2 id="key-takeaways">Key Takeaways</h2><ul>
<li>Use Artifacts for quick prototypes and small single-page web experiences.</li>
<li>Use Claude Code for a project with real files, frameworks, tests and deployment needs.</li>
<li>Plan the sitemap and content before asking for code.</li>
<li>Test every button, form, route and mobile layout.</li>
<li>Review security, privacy, accessibility and SEO before publishing.</li>
</ul>
