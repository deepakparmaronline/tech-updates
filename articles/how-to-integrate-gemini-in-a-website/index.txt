22:T4376,<p>You can integrate Gemini into a website by calling the Gemini API from a server-side route and returning the generated text to your front end. Google&#39;s current TypeScript and JavaScript SDK is called @google/genai. The important security rule is simple: keep your API key on the server. Do not place it in browser code or a public environment variable.</p>
<p>This guide uses a Next.js App Router example, but the same design works with Express, Remix, a serverless function or another backend. The browser sends a prompt to your own endpoint. Your server validates the input, calls Gemini and returns a controlled response.</p>
<h2 id="short-answer">Short Answer</h2><p>Create a Gemini API key in Google AI Studio, install Google&#39;s @google/genai package, store the key in a server-side environment variable and create an API route that calls Gemini. Your browser code should call your own route, not the Gemini endpoint with a secret key.</p>
<p>Google&#39;s official <a href="https://github.com/googleapis/js-genai">JavaScript SDK repository</a> provides the current package, quickstart and model examples. It also warns developers not to expose API keys in client-side code. Google Cloud&#39;s <a href="https://cloud.google.com/docs/authentication/api-keys-best-practices">API key security guide</a> says keys should not be placed in client code or committed to repositories.</p>
<h2 id="what-the-question-really-means">What the Question Really Means</h2><p>Adding Gemini to a website usually means adding a feature that sends a visitor&#39;s request to your own backend, then calls the Gemini API from that backend. It is not the same as embedding a public chat page or copying an API key into a JavaScript file. Your website owns the user interface, access rules and response handling.</p>
<p>The safest design keeps the provider key on the server. The browser should know only your own endpoint, such as /api/gemini. This lets you authenticate users, apply usage limits and change models without exposing a secret to every visitor.</p>
<h2 id="how-it-works">How It Works</h2><p>A safe website integration has three parts.</p>
<p>The first part is the browser interface. It collects a question or task from the visitor and sends it to your own backend endpoint. The browser does not need to know the Gemini API key.</p>
<p>The second part is your backend. It checks the request, applies usage limits, chooses a model and sends the prompt to Gemini. It also handles timeouts and API errors. This is where the secret key stays.</p>
<p>The third part is the Gemini API. Google processes the request and returns a response to your backend. Your server can clean the response, store a usage record or apply product rules before sending it to the browser.</p>
<p>This structure gives you control over the feature. You can limit prompt length, block abusive requests, require user login, set daily usage caps and change models without shipping a new browser bundle.</p>
<h2 id="what-you-need-before-you-start">What You Need Before You Start</h2><p>You need a Google account, access to Google AI Studio, a website with a server-side runtime and a supported Node.js version if you use the current JavaScript SDK. The Google Gen AI SDK repository says version 3.0.0 and later require Node.js 22 or later. Check the version requirement before installing the package.</p>
<p>You also need to decide which API service fits your project. The Gemini Developer API is the simplest starting point when you want an API key and do not need a Google Cloud project setup. Google also supports the Gemini Enterprise Agent Platform, formerly Vertex AI, for projects that need Google Cloud authentication and regional infrastructure.</p>
<p>The services can have different models, quotas and pricing. Read the current documentation before choosing one for production. Do not copy a model name from an old tutorial without checking that it is still available to your account.</p>
<h2 id="practical-steps">Practical Steps</h2><p>The practical sequence is to create a key, install the official SDK, add a server route, call that route from the browser and then add production controls. The next steps show each part. Keep the key out of the browser from the first commit.</p>
<h3 id="step-1-create-a-gemini-api-key">Step 1: Create a Gemini API Key</h3><p>Open <a href="https://aistudio.google.com/">Google AI Studio</a> and create an API key for the project you will use. Keep the key private. Do not paste it into a public GitHub repository, a client-side script or a screenshot.</p>
<p>For local development, store the key in a server-side environment file that is excluded from source control. In a Next.js project, that can be a local environment file such as .env.local. The variable name in this guide is GEMINI_API_KEY.</p>
<p>For production, add the key through your hosting provider&#39;s environment variable or secret manager settings. Use a different key for development and production where practical. Restrict the key to the Gemini API when the platform supports that restriction, monitor usage and rotate it if you think it has been exposed.</p>
<p>Do not name the variable NEXT_PUBLIC_GEMINI_API_KEY. In Next.js, variables with the NEXT_PUBLIC_ prefix are designed to be exposed to browser code. A Gemini key should not be exposed that way.</p>
<h3 id="step-2-install-the-current-javascript-sdk">Step 2: Install the Current JavaScript SDK</h3><p>Install the official package in the server project:</p>
<pre><code>npm install @google/genai
</code></pre>
<p>Do not start a new project with the old @google/generative-ai package. Google&#39;s old JavaScript SDK repository is deprecated and points developers to the unified Google Gen AI SDK.</p>
<p>The current SDK uses the GoogleGenAI client. The official repository shows a server-side example that reads the key from an environment variable and calls a model through ai.models.generateContent. This article uses the same pattern.</p>
<p>If your host only supports Node.js 20, check the SDK version before installing. The current version 3 requires Node.js 22 or later. You can either move the project to a supported Node version or pin a compatible earlier SDK version after checking its documentation. Do not ignore the engine requirement without testing the application.</p>
<h3 id="step-3-add-a-server-side-api-route">Step 3: Add a Server-Side API Route</h3><p>In a Next.js App Router project, create a route such as app/api/gemini/route.ts. The example below validates the prompt, calls Gemini on the server and returns a JSON response.</p>
<pre><code>import { GoogleGenAI } from &quot;@google/genai&quot;;

export const runtime = &quot;nodejs&quot;;

const apiKey = process.env.GEMINI_API_KEY;

if (!apiKey) {
  throw new Error(&quot;GEMINI_API_KEY is missing&quot;);
}

const ai = new GoogleGenAI({ apiKey });

export async function POST(request: Request) {
  try {
    const body = await request.json();
    const prompt =
      typeof body.prompt === &quot;string&quot; ? body.prompt.trim() : &quot;&quot;;

    if (!prompt || prompt.length &gt; 4000) {
      return Response.json(
        { error: &quot;Enter a prompt under 4,000 characters.&quot; },
        { status: 400 }
      );
    }

    const result = await ai.models.generateContent({
      model: &quot;gemini-3.8-flash&quot;,
      contents: prompt,
    });

    return Response.json({ text: result.text ?? &quot;&quot; });
  } catch (error) {
    console.error(&quot;Gemini request failed&quot;, error);
    return Response.json(
      { error: &quot;The AI request failed. Please try again.&quot; },
      { status: 500 }
    );
  }
}
</code></pre>
<p>The model name in the sample follows the current Google Gen AI SDK quickstart at the time this guide was checked. Model availability can change, so confirm the model list and limits in the official documentation before you deploy.</p>
<p>The example is a starting point, not a complete production system. Add authentication if the feature is for signed-in users. Add rate limiting so one visitor cannot use the entire API quota. Add request timeouts and a maximum output length. Log request IDs and error types, but do not store sensitive user prompts unless your privacy policy and product design allow it.</p>
<h3 id="step-4-call-your-route-from-the-browser">Step 4: Call Your Route From the Browser</h3><p>The front end only needs to send a request to your own endpoint. It does not import the SDK or read the API key.</p>
<pre><code>const response = await fetch(&quot;/api/gemini&quot;, {
  method: &quot;POST&quot;,
  headers: { &quot;Content-Type&quot;: &quot;application/json&quot; },
  body: JSON.stringify({ prompt }),
});

const data = await response.json();

if (!response.ok) {
  throw new Error(data.error || &quot;Gemini request failed&quot;);
}

setAnswer(data.text);
</code></pre>
<p>Show a loading state while the request is running. Disable the submit button to prevent accidental duplicate requests. If the request fails, show a short message and allow the visitor to try again. Do not expose raw server stack traces or API credentials in the browser.</p>
<p>For a static website, the front end can call a serverless function instead of a Next.js route. The important point is the same: the function stores the key and calls Gemini. A static HTML file cannot keep a long-lived secret safe after it is sent to the browser.</p>
<h3 id="step-5-protect-the-api-key-and-your-budget">Step 5: Protect the API Key and Your Budget</h3><p>Google&#39;s API key guidance recommends restricting keys, avoiding client-side exposure, deleting keys you no longer need, monitoring usage and rotating keys periodically. Treat a Gemini key like a password that can create usage charges.</p>
<p>Use a server-side environment variable or a secrets manager. Never commit the key to GitHub. If it appears in a commit, remove the exposed credential and rotate it. Deleting the line from the latest version is not enough because the secret may remain in repository history.</p>
<p>Add a rate limit by user, IP address or account. The right limit depends on your product, but there should be a clear cap. Add a maximum prompt size and reject empty or malformed input. If the website is public, use a CAPTCHA or another abuse control when the traffic pattern requires it.</p>
<p>Set a budget alert or usage alert in the platform you use. Review the model, input size and output size because long prompts and long responses can increase cost. Cache results only when the response can safely be reused and the data is not private or user-specific.</p>
<h3 id="step-6-choose-a-model-for-the-job">Step 6: Choose a Model for the Job</h3><p>Do not select a model only because it has the newest name. Start with the task. A short FAQ answer, a classification label, a long document summary and a multi-step agent task have different needs.</p>
<p>Test a small set of real prompts. Measure answer quality, latency, output length, error rate and cost. If a smaller model meets your quality target, it may be a better fit for a high-volume website feature. If the task needs stronger reasoning or a larger context window, test a more capable model.</p>
<p>Keep the model ID in server configuration rather than hardcoding it in several files. That makes it easier to change models after a deprecation or product update. Check the official model list before you deploy a change.</p>
<h2 id="production-checks-before-launch">Production Checks Before Launch</h2><p>Test the route with an empty prompt, a very long prompt, an invalid JSON body and a normal request. Check what happens when the API key is missing, the provider returns an error or the request takes too long. The front end should show a useful message without revealing server details.</p>
<p>Check that the key is not present in the built JavaScript bundle. Search your public assets and browser network requests for the key name. The browser should call your own endpoint and should never receive the secret.</p>
<p>Add monitoring for request count, error rate, latency and approximate usage. Keep logs free of sensitive prompt text unless you have a clear reason and user consent. Set a policy for how long request logs are kept.</p>
<p>Finally, test the feature on the hosting environment, not only on your laptop. Node version, environment variables, request timeouts and serverless limits can differ between local and production environments.</p>
<h2 id="common-problems">Common Problems</h2><p>The most serious mistake is putting the API key in front-end code. A key in a React component, public JavaScript bundle or NEXT_PUBLIC_ variable can be copied by anyone who visits the site.</p>
<p>Another mistake is using an old SDK because a tutorial still ranks in search. Google&#39;s legacy JavaScript package is deprecated. Use the current @google/genai package and check the version requirements.</p>
<p>Do not let every visitor send unlimited requests. A public AI endpoint needs authentication, rate limits, usage monitoring and clear error handling. Without those controls, one script can consume the available quota.</p>
<p>Do not assume a model response is safe to publish. Validate output before using it in a page, email or workflow. If the model can call tools or access customer data, add authorization checks in your own server code. The model should not decide whether a user is allowed to access a record.</p>
<h2 id="what-does-not-work">What Does Not Work</h2><p>Putting a long-lived Gemini key in a React component, public JavaScript bundle or NEXT_PUBLIC_ environment variable does not keep it secret. Visitors can inspect the page and copy the key. A static site also cannot safely store a private key in the files it sends to a browser.</p>
<p>Using a deprecated SDK because an old tutorial still appears in search is another weak starting point. Do not assume that an example for an earlier package or model name will work with the current SDK. Check the official package and model documentation before copying code into production.</p>
<h2 id="safety-and-limitations">Safety and Limitations</h2><p>Gemini responses can be wrong, incomplete or unsafe for a specific workflow. Validate output before using it to update customer records, publish content or trigger another system. Keep authorization decisions in your own server code rather than asking the model whether a visitor is allowed to access data.</p>
<p>Your usage limits and costs depend on the model, prompt size, output size and request volume. Add rate limits, budget alerts and monitoring before making the endpoint public. Do not log sensitive prompts unless your privacy policy and product design allow it.</p>
<h2 id="key-takeaways">Key Takeaways</h2><ul>
<li>Use the official @google/genai SDK for new JavaScript projects.</li>
<li>Keep the Gemini key on the server and call it through your own route.</li>
<li>Use Node.js 22 or later with SDK version 3.</li>
<li>Validate input, add rate limits and monitor usage before launch.</li>
<li>Recheck the model list and pricing before production changes.</li>

<h2 id="faq">FAQ</h2><h3 id="can-i-add-gemini-to-my-website">Can I add Gemini to my website?</h3><p>Yes. Use the Gemini API from a backend route or serverless function, then send the result to your front end. This keeps your API key out of public client code.</p>
<h3 id="which-javascript-sdk-should-i-use-for-gemini">Which JavaScript SDK should I use for Gemini?</h3><p>Google&#39;s current TypeScript and JavaScript SDK is @google/genai. The older @google/generative-ai package is deprecated.</p>
<h3 id="can-i-call-gemini-directly-from-browser-javascript">Can I call Gemini directly from browser JavaScript?</h3><p>The SDK can run in a browser for some setups, but Google&#39;s SDK warns against exposing API keys in client-side code in production. A server-side route is safer.</p>
<h3 id="what-node-js-version-does-the-current-google-gen-ai-sdk-need">What Node.js version does the current Google Gen AI SDK need?</h3><p>The current SDK repository says version 3.0.0 and later require Node.js 22 or later. Check the package requirements before installing.</p>
<h3 id="where-should-i-store-my-gemini-api-key">Where should I store my Gemini API key?</h3><p>Store it as a server-side environment variable or in a secrets manager. Do not use a NEXT_PUBLIC_ variable or commit the key to source control.</p>
<h3 id="can-i-use-gemini-in-a-static-website">Can I use Gemini in a static website?</h3><p>A static front end can call a serverless function or backend endpoint that talks to Gemini. Do not put a long-lived API key in a public JavaScript bundle.</p>
