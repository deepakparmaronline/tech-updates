1b:T2694,<h2 id="short-answer">Short Answer</h2><p>Claude has several ways to use context, but chat history, a saved memory feature, Projects and Claude Code project instructions are not the same thing. Which options you can use depends on the current product, account and rollout. Check the settings and official Anthropic help pages for the exact memory controls available to you.</p>
<p>Start with the official <a href="https://claude.ai/">Claude website</a>, <a href="https://support.anthropic.com/">Anthropic Support</a> and the <a href="https://docs.claude.com/en/docs/claude-code/memory">Claude Code documentation</a>. Those pages are the appropriate places to confirm current behavior. They could not be reopened during this repository only run, so this article explains the concepts and safe checks rather than claiming a live feature audit.</p>
<h2 id="what-the-question-really-means">What the Question Really Means</h2><p>When someone asks whether Claude has memory, they may mean one of four things. They may want to reopen a previous chat. They may want Claude to remember a preference across separate conversations. They may want a Project to keep files and instructions together. Or they may mean Claude Code should follow repository rules while working on a codebase.</p>
<p>These needs have different solutions. Chat history helps you find previous conversations. A saved memory feature, when available, may carry selected context forward. A Project can group material for a continuing task. Claude Code can read project instructions such as CLAUDE.md to guide work in a repository. Treating these as identical can lead to missing context or accidental disclosure.</p>
<p>The first step is to name the job you want memory to do. If you need a record of a past decision, keep the original chat or a project note. If you need repeated preferences, review the memory controls in your account. If you need consistent code rules, use project instructions and version control. Each approach should have a clear owner and a way to correct stale information.</p>
<h2 id="how-it-works">How It Works</h2><p>A conversation has a context: the messages and materials available to the assistant while answering. A chat history view may let you return to a previous conversation, but that does not guarantee every old message is automatically loaded into a new one. A saved memory feature, where offered, is a separate mechanism that may select details for future use.</p>
<p>Projects are useful for ongoing work because they can keep related files, notes and instructions in one place. A project does not mean the assistant has unlimited recall or that every file is always used in every answer. Large projects still need clear organization, and users should point the assistant to the relevant source when accuracy matters.</p>
<p>Claude Code is different again. Project instruction files can describe how a coding assistant should work in a repository. For example, a file can tell the assistant which tests to run, which folders are sensitive and what coding style to follow. These instructions help shape work inside that project. They should not be used as a place to store credentials or private personal details.</p>
<h2 id="practical-steps">Practical Steps</h2><ol>
<li><strong>Check the product you are using.</strong> Claude on the web, mobile, and Claude Code may have different context and memory controls.</li>
<li><strong>Review settings.</strong> Open the current account settings and read the available controls before changing anything. If memory is listed, inspect what it saves and how it can be reviewed or disabled.</li>
<li><strong>Separate chat history from saved context.</strong> If you only need an old answer, search or reopen the original conversation. Do not assume it has been saved as a reusable memory.</li>
<li><strong>Use Projects for continuing work.</strong> Keep the most relevant documents and project instructions together. Name files clearly and remove outdated guidance so the assistant does not follow conflicting instructions.</li>
<li><strong>For coding, review CLAUDE.md.</strong> Keep repository instructions concise, scoped and version controlled. Add test commands and safety boundaries, not credentials.</li>
<li><strong>Test what carries forward.</strong> In a non sensitive chat, ask Claude to restate the preference or project detail you expect it to know. Compare the response with the source of truth.</li>
<li><strong>Correct stale information.</strong> If the account offers memory editing or deletion controls, use the documented method. If not, update the project note or provide fresh context explicitly.</li>
<li><strong>Verify important decisions.</strong> Memory is a convenience, not proof. Check the original source before acting on a remembered price, policy, deadline or technical requirement.</li>
</ol>
<h2 id="common-problems">Common Problems</h2><p>Claude may appear not to remember something because the information was in another conversation, the project did not include the relevant file, a memory control is unavailable, or the detail was never saved. It may also summarize a detail incorrectly. A confident answer does not prove the memory is complete.</p>
<p>The opposite problem is stale context. A preference, product plan or technical instruction can change. If old information continues to appear, inspect the saved source and project instructions rather than repeating the correction only in chat. For code, check whether the repository has several instruction files that conflict or a project note that no longer matches the current code.</p>
<p>If a Project contains many files, use clear names and a short index. Tell Claude which document is authoritative for the task. For code repositories, use version control so changes to project instructions can be reviewed just like code. This makes it easier to identify when a bad answer came from outdated instructions rather than a model limitation.</p>
<h2 id="what-does-not-work">What Does Not Work</h2><p>Do not assume that opening an old conversation means Claude will remember it in a new chat. Do not assume a Project, chat history and saved memory share the same controls. Do not expect a coding instruction file to carry personal preferences across unrelated projects.</p>
<p>Avoid copying large amounts of private information into a memory note just because it might be convenient. Keep only what is needed for the task. Avoid passwords, access tokens, API keys, customer records and confidential data. If the task requires sensitive material, use an approved secure system and follow the organization&#39;s data policy.</p>
<p>Do not treat remembered content as a source citation. If Claude recalls a contract clause, a number or a product feature, verify it against the original document. A useful memory system reduces repeated work, but it cannot replace a source of truth.</p>
<h2 id="safety-and-limitations">Safety and Limitations</h2><p>Memory can affect what an assistant emphasizes, so users should know what information may carry into future conversations. Review current settings and privacy guidance before using memory for personal or workplace data. If a shared account or organization workspace is involved, confirm who controls the settings and whether administrators apply additional rules.</p>
<p>This is a concept and safety guide, not a live test of every Claude account. Current features may differ by product, region or rollout. The official Anthropic pages above are primary starting points, but external pages were not reopened during this GitHub only run.</p>
<h2 id="key-takeaways">Key Takeaways</h2><ul>
<li>Identify whether you need chat history, saved memory, Project context or Claude Code instructions.</li>
<li>Keep memory short, useful and free of secrets.</li>
<li>Verify important remembered facts against the original source.</li>
</ul>

<h2 id="faq">FAQ</h2><h3 id="does-claude-remember-all-my-old-conversations">Does Claude remember all my old conversations?</h3><p>Do not assume that it does. Chat history and any saved memory features have different purposes. Check current product settings and provide the relevant source when a new conversation needs a specific fact.</p>
<h3 id="can-claude-remember-writing-preferences">Can Claude remember writing preferences?</h3><p>A memory feature may support preferences where it is available, but the exact behavior and controls can change. Review the settings and test with a non sensitive preference.</p>
<h3 id="are-claude-projects-a-memory-system">Are Claude Projects a memory system?</h3><p>Projects can organize ongoing work and relevant context, but they should not be treated as unlimited recall. Keep the source documents clear and identify which one is authoritative.</p>
<h3 id="what-is-claude-code-memory">What is Claude Code memory?</h3><p>Claude Code can use project instruction files and other documented context mechanisms to guide work in a repository. These are different from a consumer chat memory feature.</p>
<h3 id="can-memory-contain-secrets">Can memory contain secrets?</h3><p>Avoid putting secrets into any memory or project file. Use environment variables or a secret manager for credentials, and rotate a key if it has been exposed.</p>
<h3 id="what-should-i-do-when-claude-remembers-something-wrong">What should I do when Claude remembers something wrong?</h3><p>Check the original source, correct or update the stored note if the product provides a control, and explicitly provide current context. Do not rely on a remembered detail for a high impact decision.</p>
