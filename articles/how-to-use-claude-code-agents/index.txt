19:T34d0,<p>Claude Code agents help split a development task into smaller jobs. You can ask one worker to inspect a codebase, another to review tests, or a focused reviewer to check a change for security issues. The main benefit is not simply having more agents. It is keeping each task clear, limiting the tools it can use, and bringing back results that are easier to review.</p>
<p>The phrase Claude Code agents can mean two different things. A subagent works inside one Claude Code session and returns a result to the main conversation. An agent team coordinates several separate Claude Code sessions that can share tasks and send messages to one another. Start with subagents for most focused tasks. Use teams only when the work really needs independent sessions.</p>
<h2 id="short-answer">Short Answer</h2><p>To use Claude Code agents, start by defining the job you want done, then decide whether a built-in subagent or a custom subagent is the right fit. For repeated work, create a Markdown definition in the project-level agent directory. Give it a clear name, a short description, only the tools it needs, and instructions that describe the result you expect.</p>
<p>You do not need to build a complex agent setup before using Claude Code. Ask Claude to explore a code path, review a change, or investigate a failing test. When the same side task keeps returning, save the role as a custom subagent. If several independent sessions need to coordinate and challenge one another, review agent teams, but remember that they are experimental and disabled by default.</p>
<h2 id="what-the-question-really-means">What the Question Really Means</h2><p>A subagent is a specialized assistant with its own context window, system prompt, tool access, and permissions. Anthropic&#39;s <a href="https://code.claude.com/docs/en/sub-agents">custom subagents guide</a> explains that a subagent can handle a side task that would otherwise fill the main conversation with logs, search results, or file contents. It returns a summary to the caller, keeping the main session focused.</p>
<p>An agent team is different. The <a href="https://code.claude.com/docs/en/agent-teams">agent teams guide</a> describes several independent Claude Code instances that share a task list and communicate directly. A team lead coordinates the work and combines the results. This can help when separate reviewers need to discuss findings or when a feature can be split into independent parts.</p>
<p>Do not confuse either feature with a skill. A skill stores reusable instructions or a workflow. A subagent is a worker that uses its own context to complete a task. A skill can be loaded by a subagent, but it does not automatically become a separate agent.</p>
<h2 id="how-it-works">How It Works</h2><p>Claude Code uses the description of a subagent to decide when it is relevant. That description should be specific enough to match the right task. For example, a code reviewer should be described as a reviewer for changed files, not as a general assistant for every coding task.</p>
<p>A custom subagent can use a restricted tool list. This is important because a reviewer usually needs to read files and search the repository, but does not need permission to edit code or run arbitrary shell commands. A test runner may need a different set of tools. Anthropic documents fields for description, tools, model, permission mode, hooks, skills, and other controls in its <a href="https://code.claude.com/docs/en/sub-agents">frontmatter reference</a>.</p>
<p>Subagents run within a single session and return their findings to the main session. They use their own context window, so high-volume exploration does not need to fill the main conversation. Their requests still count toward the same usage limits as the main session.</p>
<p>Agent teams have more coordination overhead. They are useful when teammates need to share findings and make decisions together, but they use more tokens because each teammate is a separate Claude Code instance. Anthropic says agent teams are experimental and disabled by default. Read the <a href="https://code.claude.com/docs/en/agent-teams">official team setup and limitations</a> before enabling them.</p>
<h2 id="practical-steps">Practical Steps</h2><h3 id="1-choose-a-task-that-can-be-separated">1. Choose a task that can be separated</h3><p>Start with a task that has a clear input and output. Good examples include reviewing changed files, finding the source of a failing test, checking whether an API is used consistently, or researching how a module handles authentication.</p>
<p>Avoid creating a subagent for a task that depends on every detail in the main conversation. If the worker needs the full conversation history, a normal request in the main session may be easier. A good subagent can work from a short brief and a defined set of files.</p>
<h3 id="2-create-a-project-level-subagent">2. Create a project-level subagent</h3><p>For a role that should be available only in one repository, create a Markdown file in the project-level .claude/agents directory. A user-level agent definition can be stored in the user Claude configuration directory when you want to reuse the role across repositories.</p>
<p>A simple read-only reviewer can look like this:</p>
<pre><code>---
name: code-reviewer
description: Review changed code for bugs, security risks, and missing tests.
tools:
  - Read
  - Grep
  - Glob
model: inherit
---

Review the changed files only. Identify concrete bugs, security issues,
missing tests, and risky assumptions. For every finding, include the file,
the relevant line or function, why it matters, and a practical fix.
Do not edit files. Do not claim a test passed unless you ran it.
</code></pre>
<p>Keep the description short because Claude uses it when deciding whether to delegate. Put detailed instructions in the body. The example uses read-only tools on purpose. If the reviewer only needs to inspect code, do not give it write or shell access.</p>
<h3 id="3-ask-claude-to-use-the-role">3. Ask Claude to use the role</h3><p>Open Claude Code in the repository and describe the task. You can ask it to use the code-reviewer subagent to review the changes in a named folder, or ask for a security review of a specific branch. Give it a clear scope and say what evidence should appear in the report.</p>
<p>You can also ask Claude to delegate automatically when a task matches the subagent description. Explicit requests are useful while testing a new definition because you can confirm that the intended role was selected.</p>
<h3 id="4-give-each-worker-a-different-job">4. Give each worker a different job</h3><p>If you need several checks, separate them by purpose. One subagent can review security, another can look for missing tests, and another can check performance. Avoid asking all of them to review everything, because that creates duplicate work and reports that are harder to combine.</p>
<p>Ask the main session to compare the findings, remove duplicates, and verify each claim against the code. A subagent report is evidence to inspect, not proof that the issue is real. A good report includes exact file paths, functions, and commands so the result can be checked.</p>
<h3 id="5-use-agent-teams-only-for-independent-sessions">5. Use agent teams only for independent sessions</h3><p>When you need multiple Claude Code sessions to coordinate directly, agent teams may be a better fit. Anthropic documents a setting called CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS that enables the feature. It is experimental and disabled by default, so do not switch it on for routine tasks without reading the current limitations.</p>
<p>A good team task has work that can happen in parallel, such as separate frontend, backend, and test investigations. A poor team task is a sequence of edits to the same file. Multiple agents editing the same area can create conflicts and increase the time spent coordinating.</p>
<h2 id="common-problems">Common Problems</h2><p>A subagent may not start because its description is vague or because the task does not match the role. Improve the description with a clear trigger and a specific output. A reviewer that says it checks changed files, security risks, and missing tests is easier to route than one described as a general coding assistant.</p>
<p>Another problem is giving an agent too many tools. A read-only research role does not need file editing or unrestricted shell commands. A tool list should be the smallest set that lets the agent finish its job. If a subagent cannot complete a task because it lacks a tool, ask whether that tool is truly necessary before expanding permissions.</p>
<p>A third problem is treating a summary as a complete audit. The main session should inspect the cited files, rerun tests, and verify the suggested fix. Ask agents to include exact file paths, functions, and commands so the result can be checked.</p>
<h2 id="what-does-not-work">What Does Not Work</h2><p>More agents do not automatically make a task faster. If every worker needs the same context, edits the same files, or waits for another worker, the coordination cost can outweigh the benefit. Use a single session for a straightforward sequential task.</p>
<p>Agent teams are not just a larger subagent setting. They are separate sessions with their own context and shared coordination. They are experimental, can use more tokens, and have limitations around session resumption and task coordination. Do not enable them simply because the word agent sounds more advanced.</p>
<p>A custom subagent also does not guarantee a safe action. Its prompt is not a security boundary by itself. Use tool restrictions, permission controls, and review steps. Keep secrets out of context and do not let an agent merge or deploy code without the checks your repository requires.</p>
<h2 id="safety-and-limitations">Safety and Limitations</h2><p>Start with read-only roles. If an agent needs to edit files, limit the scope and review the diff before running it. For commands that can delete data, change production systems, or expose credentials, keep a human approval step.</p>
<p>Treat agent output as untrusted until you verify it. A subagent can misunderstand a code path, miss a dependency, or report a test result incorrectly. Require evidence and run the project tests yourself. For team workflows, make sure each teammate has enough context and does not change the same files as another teammate.</p>
<p>Anthropic&#39;s <a href="https://code.claude.com/docs/en/claude-code-on-the-web">Claude Code cloud guide</a> also explains that cloud sessions can run in separate environments and that access depends on plan and configuration. That is another reason to review environment permissions and network access before sending sensitive repositories to a cloud workflow.</p>
<h2 id="key-takeaways">Key Takeaways</h2><ul>
<li>Use subagents for focused work that can be completed from a clear brief.</li>
<li>Save repeated roles in .claude/agents and give them only the tools they need.</li>
<li>Use agent teams for complex work that needs independent sessions and direct communication.</li>
<li>Keep human review, tests, and permission controls in the workflow.</li>
</ul>

<h2 id="faq">FAQ</h2><h3 id="what-are-agents-in-claude-code">What are agents in Claude Code?</h3><p>The term can refer to subagents or agent teams. Subagents handle focused work in separate context windows and return results to the main session. Agent teams coordinate independent sessions through a shared task list and direct messages.</p>
<h3 id="how-do-i-create-a-custom-claude-code-agent">How do I create a custom Claude Code agent?</h3><p>Create a Markdown file with YAML frontmatter in the project .claude/agents directory. Add a name, a short description, the tools the role can use, and focused instructions. Start with a read-only tool list unless editing is required.</p>
<h3 id="where-should-i-save-claude-code-subagents">Where should I save Claude Code subagents?</h3><p>Use the project-level .claude/agents directory for roles that belong to one repository. Use the user-level Claude agents directory for roles you want to reuse across projects. Managed and plugin definitions have their own scopes.</p>
<h3 id="can-claude-code-agents-work-in-parallel">Can Claude Code agents work in parallel?</h3><p>Yes. Subagents can handle focused tasks in parallel and return their findings to the main session. Agent teams can coordinate separate Claude Code sessions that share tasks and communicate directly, but they add overhead.</p>
<h3 id="are-claude-code-agent-teams-enabled-by-default">Are Claude Code agent teams enabled by default?</h3><p>No. Anthropic documents agent teams as experimental and disabled by default. You must enable the experimental setting and should review the current limitations before using them on important work.</p>
<h3 id="are-claude-code-agents-safe-for-production-repositories">Are Claude Code agents safe for production repositories?</h3><p>They can help, but safety depends on permissions and review. Limit tools, avoid exposing secrets, inspect every proposed change, and run tests before merging or deploying code.</p>
