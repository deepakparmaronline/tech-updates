1b:T3168,<h2 id="short-answer">Short Answer</h2><p>The fastest way to learn whether Perplexity is down is to open the official <a href="https://status.perplexity.com/">Perplexity status page</a>. It reports separate components for the website, mobile application, computer product, and API. When this article was checked on October 23, 2026, the page showed all listed services as operational. That is only a dated observation, not a promise about the service now.</p>
<p>If the status page shows an incident, wait for its updates and avoid making major changes to your device or account. If the page is green but Perplexity does not work for you, test a private browser window, another device, and another network. Those checks quickly separate a broad service outage from a local browser, application, login, or network problem.</p>
<h2 id="what-the-question-really-means">What the Question Really Means</h2><p>“Is Perplexity down?” can describe several different symptoms. The website may not load. A search may remain stuck. The mobile app may close. Login links may fail. The API may return errors even while the consumer site works. Each symptom points to a different component and requires a different test.</p>
<p>A public status page is the best starting point because Perplexity can publish confirmed incidents and affected services there. Reports on social networks and outage tracking sites can provide context, but they may combine unrelated local problems or repeat old screenshots. Treat them as supporting evidence, not the final authority.</p>
<p>You also need to distinguish an outage from a usage limit or account issue. A rate limit, expired session, subscription problem, unavailable model, or rejected API key can block a request without taking the whole service offline. Record the exact error message and time before troubleshooting.</p>
<h2 id="how-it-works">How It Works</h2><p>Perplexity depends on several layers: your device, browser or app, local network, domain name resolution, Perplexity&#39;s edge and application systems, account services, model providers, and any connected sources. A failure at one layer can look like the entire product is down.</p>
<p>The official status dashboard breaks the service into components. Check the component that matches your problem. If the website is operational but the API reports an incident, browser searches may still work. Conversely, an account or web incident does not prove that every API request is failing.</p>
<p>For the API, the response status and body matter. An authentication error is different from a rate limit, bad request, or server error. Keep the request identifier when one is provided, but never post the API key or full sensitive payload in a public report.</p>
<p>Your browser can also cause failures. Blocking extensions, strict cookie settings, old service worker data, and corporate security filters may prevent scripts or authentication from completing. A private window is a useful comparison because it usually starts with clean site data and fewer extensions.</p>
<h2 id="practical-steps">Practical Steps</h2><h3 id="1-check-the-official-status-page">1. Check the official status page</h3><p>Open <a href="https://status.perplexity.com/">status.perplexity.com</a> directly. Look for an active incident, scheduled maintenance, or a degraded component that matches what you are using. Note when the incident began and subscribe to updates if the page offers that option.</p>
<p>If the status page itself will not load, try it on mobile data or from a second device. A local network problem can block both the product and its status domain.</p>
<h3 id="2-save-the-evidence">2. Save the evidence</h3><p>Write down the time, device, browser or app version, affected feature, and exact error. For an API request, save the response code, request identifier, and a redacted example. For a browser problem, take a screenshot that does not expose private queries or account information.</p>
<p>This evidence helps you see whether the failure is consistent and gives support a useful starting point.</p>
<h3 id="3-try-a-clean-browser-test">3. Try a clean browser test</h3><p>Open Perplexity in a private browsing window. If it works there, an extension, cookie, cache entry, or saved session in the normal profile is a likely cause. Disable extensions one at a time, especially script blockers, privacy tools, and browser assistants.</p>
<p>Sign out and back in only after saving unfinished work. If needed, clear site data for Perplexity rather than clearing the entire browser history. That limits disruption to other services.</p>
<h3 id="4-compare-devices-and-networks">4. Compare devices and networks</h3><p>Test another supported browser or device. Then switch between the usual network and a trusted alternative, such as mobile data. If one network fails on every device, restart the router and check whether a workplace, school, internet provider, DNS service, firewall, or content filter is blocking the connection.</p>
<p>Temporarily disconnect a VPN as a diagnostic step if your policy allows it. Do not disable company security software or bypass an organizational filter. Report the blocked destination to the administrator instead.</p>
<h3 id="5-check-the-mobile-or-desktop-app">5. Check the mobile or desktop app</h3><p>Force close and reopen the app. Check the official app store for an update and confirm that the operating system has enough free storage. Restart the device if the app remains stuck.</p>
<p>Do not uninstall immediately if the app contains local drafts or settings you need. Confirm how they are synchronized first. If reinstalling becomes necessary, use the official app store and verify the publisher.</p>
<h3 id="6-diagnose-api-errors-separately">6. Diagnose API errors separately</h3><p>First, check the API component on the official status page. Then inspect the HTTP response. A 400 class response often points to the request, authentication, permission, quota, or rate limit. A 500 class response can indicate a server problem, although malformed traffic or an intermediary can still complicate the result.</p>
<p>Confirm the current endpoint, model name, headers, plan, and limits against Perplexity&#39;s official API documentation. Retry only with a bounded backoff. Aggressive loops can amplify an incident and consume quota when the service recovers.</p>
<h3 id="7-contact-support-with-a-focused-report">7. Contact support with a focused report</h3><p>If the problem persists while the status page shows no matching incident, contact Perplexity through its current official channels. Perplexity&#39;s <a href="https://www.perplexity.ai/en-GB/hub/security-vdp">security and vulnerability page</a> directs account specific, functional, safety, and quality issues to <code><a href="mailto:support@perplexity.ai">support@perplexity.ai</a></code>.</p>
<p>Include the time zone, product area, device, version, steps to reproduce, exact error, and the safe tests already completed. Redact tokens, private prompts, payment details, and personal information.</p>
<h2 id="common-problems">Common Problems</h2><p>If the page is blank or endlessly loading, try a private window and disable extensions one at a time. Stale site data can also be responsible. Clear only Perplexity&#39;s site data after confirming that you will not lose something important.</p>
<p>If login email links fail, use the link in the same browser and device where the login began. Request a fresh link and check spam filtering. Avoid forwarding a sign in link because it may be temporary and tied to a session.</p>
<p>If searches work on mobile data but not WiFi, investigate the router, DNS resolver, VPN, proxy, or network filter. Changing account passwords will not repair a blocked network route.</p>
<p>If the service is slow rather than unavailable, test a simple query and compare components. A complex file upload or model request can take longer than a basic search. Check whether only one model or feature is affected.</p>
<p>If the API says you are unauthorized or rate limited, a green status page does not make that message an outage. Check credentials, project access, billing, and current limits. Never send a secret key to support in plain text.</p>
<h2 id="what-does-not-work">What Does Not Work</h2><p>Refreshing continuously is not a reliable fix. It can discard unsaved text, create duplicate requests, or make rate limits worse. Save the prompt and retry at reasonable intervals.</p>
<p>Changing many settings at once also makes diagnosis harder. If you clear all browser data, reinstall the app, reset the router, and change the password together, you will not know what caused or fixed the issue.</p>
<p>An old social post cannot confirm today&#39;s outage. Always compare its timestamp with the official live page. Search results may surface an incident from months earlier because it received many links.</p>
<p>Do not download unofficial Perplexity installers or browser repair tools. A service disruption is a common moment for phishing pages to appear. Use the official site and recognized app stores.</p>
<h2 id="safety-and-limitations">Safety and Limitations</h2><p>Never publish API keys, authentication links, cookies, private prompts, or complete diagnostic logs. Redact sensitive material before sharing a screenshot or support report. Rotate a credential immediately if it has been exposed.</p>
<p>Do not bypass workplace or school controls to reach the service. A blocked AI site may reflect an intentional data policy. Ask the administrator for an approved route or alternative.</p>
<p>Status dashboards report what the operator has detected and published. A new incident, regional fault, or account specific problem may not appear immediately. That is why device and network comparisons still matter when the page shows normal operation.</p>
<p>The dated status in this article will become stale. Use the live dashboard for the current answer and treat this guide as a troubleshooting sequence, not a real time monitor.</p>

<li>Record the error and time before changing settings.</li>
<li>Compare a private window, another device, and another trusted network to isolate local problems.</li>
<li>Treat API response codes, plan limits, and credentials separately from consumer website incidents.</li>
<li>Contact official support with a concise, redacted report if the problem persists.</li>
