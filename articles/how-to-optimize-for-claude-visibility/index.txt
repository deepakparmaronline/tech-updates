29:T41ef,<p>If you want your website to appear in answers from Claude, start with crawl access and useful content. Anthropic uses separate bots for model development, search indexing and pages that Claude retrieves when a person asks a question. Those bots do not have the same job, so a single robots.txt rule can affect different types of access.</p>
<p>There is no public Claude ranking formula and no technical switch that guarantees a citation. This guide explains what Anthropic documents today, how to check your crawler rules and which SEO practices make your pages easier to find, read and verify.</p>
<h2 id="short-answer">Short Answer</h2><p>To improve the chance that Claude can use a public page, make sure the page is available without a login, returns a normal response, has useful text and is not blocked from the relevant Anthropic bots. Pay special attention to <strong>Claude-SearchBot</strong> and <strong>Claude-User</strong>. They are the bots tied to search indexing and user-directed retrieval.</p>
<p>Do not confuse those bots with <strong>ClaudeBot</strong>, which Anthropic describes as a crawler for content that may contribute to model development. You can make a separate choice about training collection without automatically blocking every form of Claude search access.</p>
<p>Anthropic&#39;s <a href="https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler">crawler documentation</a> is the primary source for these differences. Review it before changing your site rules.</p>
<h2 id="what-the-question-really-means">What the Question Really Means</h2><p>Claude visibility can mean three different things: a page being available to Claude when a person asks for it, a page being indexed for Claude search, or public content being collected for model development. Those are separate access paths, so a site owner should not treat every Anthropic crawler as one bot.</p>
<h2 id="how-it-works">How It Works</h2><p>Anthropic documents three main robots that website owners should understand.</p>
<h3 id="claudebot-model-development-collection">ClaudeBot: model development collection</h3><p>ClaudeBot helps Anthropic collect public web content that may contribute to model training and development. If a site restricts ClaudeBot, Anthropic says that signals the site&#39;s future materials should be excluded from its model training datasets.</p>
<p>That is a training preference. It is not the same as telling the search crawler that a page should never appear in a web search response. A publisher may decide to block training collection while still allowing user-initiated retrieval and search indexing.</p>
<h3 id="claude-user-pages-fetched-for-a-person-s-request">Claude-User: pages fetched for a person's request</h3><p>Claude-User supports requests made by people using Claude. When a user asks a question, Claude may retrieve a public web page with this user agent. Anthropic says disabling Claude-User prevents its system from retrieving the site&#39;s content in response to a user query. That can reduce the site&#39;s visibility for user-directed web search.</p>
<p>This distinction matters for publishers. A page may be available to a person in a normal browser but still be blocked from a user-initiated fetch if the site rules or security layer reject the bot.</p>
<h3 id="claude-searchbot-search-indexing">Claude-SearchBot: search indexing</h3><p>Claude-SearchBot is used to improve search result quality. Anthropic says that disabling it prevents content from being indexed for search optimization and can reduce visibility and accuracy in user search results.</p>
<p>If search visibility is your goal, check this bot separately. Do not assume that allowing ClaudeBot is enough. The bots have different jobs and separate controls.</p>
<h2 id="practical-steps">Practical Steps</h2><p>Robots.txt is a public file at the top level of a site, usually at the root domain. It tells compliant crawlers which paths they may request. Anthropic says its bots respect standard robots.txt directives and the Crawl-delay extension.</p>
<p>If your site wants to limit model-training collection but still allow search and user-directed retrieval, the policy can be expressed with separate user-agent groups. A simple example is:</p>
<pre><code>User-agent: Claude-SearchBot
Allow: /

User-agent: Claude-User
Allow: /

User-agent: ClaudeBot
Disallow: /
</code></pre>
<p>This is an example, not a ready-made replacement for your current robots.txt. Merge the rules with the existing file, check for broader rules that may affect the same paths and test the final result. A site can have separate rules for images, PDFs, subdomains and private areas.</p>
<p>Anthropic recommends using robots.txt to express crawler preferences. It also warns that blocking crawler IP addresses is not a reliable substitute for robots.txt because it can interfere with the crawler&#39;s ability to read the file. The company publishes an <a href="https://claude.com/crawling/bots.json">official crawler IP list</a> so site owners can verify whether a request is coming from Anthropic.</p>
<h2 id="common-problems">Common Problems</h2><p>A request can be blocked before it reaches your web server. A CDN, web application firewall, bot-management tool, rate limit or hosting rule may reject it. Review those systems if the robots.txt file appears correct but the server logs show repeated errors.</p>
<p>Check these areas:</p>
<ul>
<li>The robots.txt file returns a successful response and is available on every relevant subdomain.</li>
<li>Important pages return a normal HTTP response instead of a login page, challenge screen or error.</li>
<li>The canonical URL points to the page you want search systems to use.</li>
<li>The page is not marked noindex when you want it to appear in Claude web search.</li>
<li>Your CDN and firewall rules do not block the documented crawler or user-fetch requests.</li>
<li>The main text is present in the rendered page and not hidden behind a script that never loads for a crawler.</li>
<li>Important pages can be reached through internal links rather than only through a private search box.</li>
</ul>
<p>Anthropic&#39;s separate guide on <a href="https://support.claude.com/en/articles/10684638-report-block-and-remove-content-from-claude">blocking and removing content from Claude</a> explains that a noindex tag can prevent content from appearing in Claude outputs that use web search. Do not add noindex to a page you want to be discoverable.</p>
<h2 id="publish-pages-that-answer-a-real-question">Publish pages that answer a real question</h2><p>Crawler access only makes a page available. It does not make the page useful. Your content still needs to answer the question clearly and give readers a reason to trust it.</p>
<p>Start each important page with a direct explanation of the topic. Use headings that describe the sections, not vague labels such as &quot;More information&quot;. Explain terms before using them. Add examples, limitations, dates and sources where they help the reader check a claim.</p>
<p>A useful page should add something beyond a summary of other pages. That could be original research, first-hand experience, a clear comparison, an example from a real workflow or a practical explanation of a difficult topic. Do not invent a test or claim that your team checked a product if nobody performed that work.</p>
<p>Google&#39;s <a href="https://developers.google.com/search/docs/fundamentals/ai-optimization-guide">guide to generative AI features in Search</a> is written for Google, not Claude. It still provides a useful reminder about general search quality: create helpful content, make pages crawlable, use a clear technical structure and avoid empty pages written only to match query variations. Do not treat Google&#39;s guidance as a published Claude ranking formula.</p>
<h2 id="a-practical-content-and-technical-checklist">A practical content and technical checklist</h2><h3 id="use-clear-page-titles-and-headings">Use clear page titles and headings</h3><p>Give each page one clear subject. A title should tell the reader what the page answers. Headings should follow a logical order so a reader can scan the page and find the right section.</p>
<p>Avoid creating several pages that answer the same question with slightly different wording. One strong guide is usually more useful than many thin pages that repeat each other.</p>
<h3 id="add-sources-and-explain-uncertainty">Add sources and explain uncertainty</h3><p>Link to official documentation when you explain a feature, limit or policy. If a fact can change, show the date or tell the reader to check the current product page. Separate confirmed facts from your own recommendation.</p>
<p>If you compare tools, explain the criteria. If a price varies by region, say so. If you cannot confirm a feature, do not write as if it is available to everyone.</p>
<h3 id="keep-important-content-in-accessible-html">Keep important content in accessible HTML</h3><p>Make sure the main answer is visible in the page source or rendered text. Use normal links for important pages. Do not hide the entire article behind a client-side interaction or a sign-in wall if you want public crawlers to read it.</p>
<p>Semantic HTML helps both people and software understand the page. Use headings, paragraphs, lists and tables when they make the information easier to follow. Do not add markup that describes content the reader cannot see.</p>
<h3 id="maintain-crawl-paths-and-canonical-urls">Maintain crawl paths and canonical URLs</h3><p>Use internal links from relevant pages. Keep XML sitemaps accurate and include canonical URLs that point to the preferred version of each article. Remove broken links and redirect retired pages to a close replacement where one exists.</p>
<p>A sitemap does not force Claude to index a page, but it is part of a sound technical SEO setup. It also helps you keep your own site inventory clean.</p>
<h3 id="keep-pages-current">Keep pages current</h3><p>Review pages that contain limits, pricing, product features or policy details. Update the page when the official source changes. Do not change a publication date just to make an old article look new. If you add a real update, explain what changed.</p>
<h3 id="make-the-source-of-expertise-clear">Make the source of expertise clear</h3><p>Show who created or reviewed important content when that information is relevant. Explain the author&#39;s experience honestly. Use original screenshots or diagrams when they help, and label them accurately. Do not claim first-hand testing unless it happened.</p>
<h2 id="what-does-not-work">What Does Not Work</h2><p>Do not promise a client that adding an llms.txt file will make Claude cite a page. Do not buy fake mentions or publish copied paragraphs across many domains. Do not stuff a page with the phrase Claude AI in every heading. Do not block every Anthropic bot and then expect search retrieval to work.</p>
<p>Structured data can help describe a page to systems that use it, but it is not a guaranteed Claude ranking control. Keep schema accurate and consistent with visible content. The same applies to FAQs, author details and dates: they should help the reader, not exist only to create a signal.</p>
<p>Anthropic also announced on October 30, 2026 that it had begun recognizing a machine-readable preference signal for AI training. The company says the rollout is continuing and that its interpretation may change as standards develop. Treat that signal as a training preference, not as a replacement for the separate crawler rules.</p>
<h2 id="safety-and-limitations">Safety and Limitations</h2><p>No public Claude ranking formula is available, and crawler access does not guarantee a citation. Keep privacy, training preferences and search access separate. Before allowing a bot to read a page, confirm that the page is public and that your organization&#39;s content policy permits the access. Do not expose customer records, private documents or restricted areas through a broad allow rule.</p>
<h2 id="how-to-measure-progress">How to measure progress</h2><p>There is no public Claude Search Console that provides a complete ranking report. You can still check whether your site is accessible.</p>
<p>Review server and CDN logs for requests from the documented Anthropic bots. Check the response code, requested path and whether the crawler received the page content. Use the official IP list to verify requests rather than trusting a user-agent string alone.</p>
<p>You can also monitor referral traffic from Claude-related sources in your analytics platform. Treat it as a partial signal. Not every answer click will be attributed in the same way, and an impression inside an AI answer may not create a website visit.</p>
<p>For a manual review, choose a small set of questions where your page is a genuine source. Check whether Claude can find the page and whether the answer represents it accurately. Record the prompt, date and result. Do not turn a few manual checks into a claim that you have a stable ranking position.</p>
<h2 id="final-recommendation">Final recommendation</h2><p>The most useful first step is to separate the three Anthropic bots in your crawler policy. Allow Claude-SearchBot and Claude-User if you want search and user-directed retrieval to access your public pages. Make a separate decision about ClaudeBot and model-training collection.</p>
<p>Then apply strong technical SEO and publish original, well-sourced content. These steps make your pages easier to access and verify. They do not guarantee a citation, because Anthropic does not publish a fixed ranking formula for Claude search.</p>

<h2 id="key-takeaways">Key Takeaways</h2><ul>
<li>ClaudeBot, Claude-User and Claude-SearchBot have different purposes.</li>
<li>Allowing Claude-SearchBot and Claude-User can support search and user-directed retrieval, but it does not guarantee visibility.</li>
<li>Use clear content and sound technical SEO instead of relying on unsupported ranking tricks.</li>
</ul>
<h2 id="faq">FAQ</h2><h3 id="how-do-i-make-my-website-visible-in-claude">How do I make my website visible in Claude?</h3><p>Keep important pages public, crawlable and useful. Check that Claude-SearchBot and Claude-User are not blocked if you want Anthropic to access the pages. No setting guarantees a citation.</p>
<h3 id="should-i-allow-claudebot">Should I allow ClaudeBot?</h3><p>That depends on your content policy. ClaudeBot is used for model development. Claude-SearchBot and Claude-User have separate search and retrieval roles, so you can make a separate choice for each bot.</p>
<h3 id="does-blocking-claudebot-remove-my-website-from-claude-search">Does blocking ClaudeBot remove my website from Claude search?</h3><p>Blocking ClaudeBot is a training preference. Anthropic documents separate bots for search and user-directed retrieval. Review all three rules before making a change.</p>
<h3 id="does-llms-txt-improve-claude-visibility">Does llms.txt improve Claude visibility?</h3><p>There is no published guarantee that it improves Claude search visibility. Do not use it as a substitute for crawlable pages, clear content and accurate sources.</p>
<h3 id="can-noindex-stop-a-page-from-appearing-in-claude-answers">Can noindex stop a page from appearing in Claude answers?</h3><p>Anthropic says noindex can prevent content from appearing in outputs that use Claude web search. Keep it off pages you want to be discoverable.</p>
<h3 id="how-can-i-check-whether-anthropic-crawls-my-website">How can I check whether Anthropic crawls my website?</h3><p>Review your server and CDN logs, check the user agent and verify the source IP against Anthropic&#39;s published crawler list. Do not rely on the user-agent name alone.</p>
